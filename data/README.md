# Данные

## Что это

`make_dataset.py` генерирует учебный набор записей о сетевых соединениях.
Структура повторяет NSL-KDD: те же имена признаков, та же задача — отличить
нормальное соединение от атаки.

```bash
python data/make_dataset.py
```

Результат — `data/connections.csv`, около 1,3 МБ, 20 000 записей, 48 % атак.

## Почему данные синтетические

Три причины, все практические:

1. **Работает офлайн.** Ничего не скачивается, файл собирается за секунду.
   На паре с нестабильным интернетом это решающее.
2. **У всех одинаковый.** Генерация детерминирована (`SEED = 20260901`),
   поэтому ваши метрики сравнимы с метриками соседа и с эталонными.
3. **Данные не лежат в Git.** `data/*.csv` в `.gitignore` — по той же причине,
   по которой туда не кладут любые датасеты. Восстанавливается одной командой,
   а значит, хранить нечего.

## Классы

| Класс | Доля | Профиль |
|---|---:|---|
| normal | 52 % | сессия завершена, ошибок мало, сервис один |
| dos (SYN flood) | 20 % | соединение не установлено, ответных байт нет |
| probe (сканирование) | 13 % | много разных сервисов, отказы, короткие сессии |
| r2l (подбор пароля) | 8 % | сессия есть, но трафик аномально мал |
| stealth (скрытная) | 7 % | **по признакам неотличима от нормы** |

Последний класс добавлен намеренно: он задаёт потолок качества около 0,95
по F1. Без него задача решается почти идеально, что создаёт ложное
впечатление о сложности детектирования атак.

## Как подставить настоящий NSL-KDD

Если нужен реальный набор, скачайте `KDDTrain+.txt`, приведите колонки
к именам из `COLUMNS` в `make_dataset.py` и положите результат в
`data/connections.csv`. Остальной код менять не придётся: он работает
с именами колонок, а не с их порядком.
