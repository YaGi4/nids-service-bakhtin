# Лабораторная работа № 2. Командная строка и окружение

## Цель
Освоить работу с путями, правами, переменными окружения, конвейерами и виртуальным окружением на материале сквозного проекта.

## Ход работы
Работа выполнена локально в macOS. Проект находится в `/Users/egor/BOBA/Учеба/Инструментальные средства разработки инфокомуникационных систем с искусственным интеллектом/project`. Абсолютный путь начинается с `/`, относительный вычисляется от текущего каталога. Поэтому `/tmp/example`, `tmp/example`, `~/tmp/example` и `../tmp/example` указывают на разные места. Файлы Python найдены командой `find . -name '*.py'`; `wc -l` подсчитывает число строк результата.

Права `640` означают чтение и запись для владельца, чтение для группы и отсутствие доступа для остальных. В `sudo echo abc > example.txt` перенаправление выполняет исходная оболочка, поэтому `sudo` не помогает; рабочий вариант — `echo abc | sudo tee example.txt`. В этом проекте такая проверка не производилась на системных файлах Mac.

`echo PATH` выводит текст `PATH`, `echo "$PATH"` — содержимое переменной. После активации `.venv` её каталог `bin` становится первым в `PATH`; поэтому команда `python` находит интерпретатор окружения. Переменная вида `EXAMPLE=42 command` действует только для дочерней команды.

Скрипт `scripts/stats.sh` возвращает код 1 без аргумента и 0 с существующим CSV. `>` перезаписывает файл, `>>` дописывает. `2>` направляет stderr; например, `ls /несуществующий-путь 2> errors.txt` не печатает ошибку на экран.

Задание с VirtualBox, Ubuntu Server, повреждением `apt` и снимками `clean` не выполнялось: пользователь разрешил локальную работу на Mac, а VirtualBox в системе отсутствует. Соответствующие скриншоты и размер снимка отсутствуют. Linux/WSL-команды не выдаются за исполненные на macOS.

## Ответы на контрольные вопросы
1. Абсолютный путь не зависит от текущего каталога; `data/connections.csv` перестанет находиться после перехода из корня проекта в `src`.
2. `640`: владелец читает и пишет, группа только читает, остальные не имеют доступа.
3. `sudo` повышает права `echo`, но файл открывает оболочка до запуска команды.
4. `PATH` — список каталогов поиска исполняемых файлов; первый найденный вариант используется.
5. Активация добавляет `.venv/bin` в начало `PATH`, меняя найденный `python` и `pip`.
6. `>` перезаписывает stdout, `>>` дописывает stdout, `2>` направляет stderr.
7. В WSL доступ к файлам `/mnt/c` проходит через слой взаимодействия с Windows и часто медленнее Linux-файловой системы; этот эффект на Mac не измерялся.
8. Снимок фиксирует состояние диска и настройки ВМ на момент создания, но не служит понятным списком зависимостей и неудобен для передачи из-за размера и привязки к гипервизору.

## Возникшие затруднения и устранение
Системный `python3` здесь имеет версию 3.15, тогда как проекту нужен Python 3.12. Виртуальное окружение создано интерпретатором Python 3.12 из доступного локального runtime; зависимости установлены в `.venv`. Шаг VirtualBox остался неподтверждённым и требует отдельного запуска ВМ для полной защиты работы.
